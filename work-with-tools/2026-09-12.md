> Files: `haqdaar/data/log.py` · `haqdaar/engine/call.py` · `haqdaar/sim.py` ·

> all three are merged, reviewed and frozen for this step.
>
> Spec:
> - `data/log.py` writes the LOG line schema already defined in
>   `haqdaar/contracts/log_schema.py`. Do not redefine it, do not add fields, import it.
> - **There are seven classes, not six.** SILENCE is the seventh. `T16` §2 enumerates six and is
>   stale; `source-docs/T16-amendment-silence-class.md` is the correction and the code already

>   `turn_n` unchanged** — silence does not spend a turn. NOISE does spend a turn.
> - `engine/call.py` is the loop: take an input, run the Filter, ask the Planner for the next
>   move, and when the Planner says stop, hand the stop to the Terminals. Write one LOG line per
>   turn. It owns the turn clock and the 8-turn cap and the 6-question wall — both read from
>   `contracts/tunables.py`, never inline.
> - **Keypad-only is a mode, and it writes its own one-off line when it is entered** (`T18`
>   corrects `T16` on this). Do not put it on the closing line only.
> - `sim.py` is a console driver: it plays a whole call with keypad input typed at the terminal,
>   against `fixtures/`. No audio, no network, no model, no phone.
>
> Hard rules:
> - `call.py` may import `contracts/`, `engine/` and `data/log.py`. It imports **no** audio, **no**
>   model, **no** `data/pipeline/`.
> - **No free model text reaches the Engine.** There is no model in this step at all.
> - **No scheme name is spoken before a non-exact terminal's preamble.** The Terminals already
>   enforce this; the call loop must not reorder what they return.
> - **One caller at a time (R1).** No queue, no worker pool, no session registry, no async
>   concurrency, no threading. One call, start to finish, in one process.
> - Numbers live in `tunables.py`, never inline.
> - No key or token in code, tests or fixtures.
>
> **Done when** `make sim` plays a complete keypad-only call end to end against `fixtures/`,
> a LOG file is written with one line per turn, and `pytest tests/test_call.py` passes.

## Order 2 · Step 8 — derivation: facets, aliases, summary

```bash
git checkout -b step-08
```

**Paste into Antigravity:**

> Implement **Step 8** of `haqdaar-v2-brain/docs/build-plan.md`. Follow `AGENTS.md`.
> Read `haqdaar-v2-brain/docs/data-contract.md`, and tickets `T06`, `T07`, `T10`, `T11`, `T12`,
> `T21`, `T24` before writing code. Work only on branch `step-08`. Do nothing outside this step.
>
> Files: `haqdaar/data/pipeline/p2_derive.py` · `tests/test_derive.py` · the `pipeline-extract`
> target in `Makefile`. Nothing else. **Do not touch `p1_scrape.py`** — Step 7 is merged and
> reviewed; read its output, do not edit it.
>
> Input: the 12 files in `data_cache/raw/*.json` written by Step 7. Each has `myscheme_slug`,
> `source_url`, `fetched_on`, `source_sha256` and the five English blocks.
>
> Spec:
> - **One model call per scheme per task.** Throttled, and **cached to `data_cache/extract/`**
>   keyed on the scheme's `source_sha256` plus the task name, so a re-run costs zero calls.
>   Nothing in this pass may scale with N in human time.
> - **Facets:** each of the seven boxes gets a closed-list value or `ANY`, **with the quoted
>   sentence from the eligibility text that justifies it**. A value with no quote **becomes
>   `ANY`**, and the quote goes to `gate_notes`. Set `facets_source: derived` and
>   **`facets_verified_by: null`** — no human has read these and the data must say so.
> - **The evidence-quote check is in code**, not in the prompt. After the model returns, assert
>   the quote appears **verbatim** in the eligibility block and the value is in the closed set.
>   A prompt is not a guard. The model selects; it never invents.
> - **Aliases:** at least 3 per language, at least 1 code-mixed per non-English language.
>   Resolve uniqueness across the whole table afterwards, not per row.
> - **Summary:** generated in English, about 35 words, then translated. Tier-1 forbidden words
>   banned.
> - **Occupation vocabulary is cut from the corpus's own eligibility prose in this same pass**,
>   in three languages, **with its cardinality recorded**. It must stay **at or under 9** so it
>   still fits a keypad menu. Do not take it from the myScheme portal — `T22` closed that and
>   ruled the derived list is the better artifact.
>
> Hard rules:
> - **Groq's real limit is 1,000 requests per day, not tokens per minute.** An uncached full pass
>   can spend a big slice of it. **The cache is load-bearing. Re-runs must be free.** Prove it:
>   the second run of `make pipeline-extract` must make zero network calls.
> - Send `reasoning_effort: "low"` with `response_format: json_object`. Measured 11 Sep: the
>   default returns **empty content** (the budget goes to a hidden reasoning field), and
>   `"medium"` returns a hard `json_validate_failed`. `"low"` returns clean JSON in ~520–570 ms.
>   `reasoning_effort` belongs in `tunables.py` next to the model id, never inline.
> - **No third-party datasets, ever.** Only `data_cache/raw/`, which came from myscheme.gov.in.
>   On any failure, fail loudly and write nothing. Never invent an eligibility rule.
> - Pipeline code only. The runtime must never import `data/pipeline/`.
> - **One caller at a time (R1).** No worker pool, no thread pool, no parallel fan-out.
> - Numbers live in `tunables.py`, never inline.
> - No key in code — read it from `.env`.
>
> **Done when** `make pipeline-extract` writes a valid record per scraped scheme, and **every
> non-`ANY` facet carries an evidence quote found verbatim in that scheme's eligibility text.**
>
> Finish by running `make pipeline-extract` **twice** and pasting both outputs — the second run
> must report every scheme served from cache.

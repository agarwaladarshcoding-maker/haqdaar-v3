>
> Input: the 12 records in `data_cache/derived/*.json` from Step 8. Output of translate:
> `data_cache/translated/<slug>.json`. Do not edit Step 8's files or its outputs.
>
> Spec — translate:
> - Sarvam Translate (`SARVAM_API_KEY` from `.env`) for the read-back sections and the `summary`,
>   English → Hindi and English → Marathi.
> - Cache every call on disk the same way `p2_derive.py` does. A second run must make **0 calls**.
>   Put the prompt/model version **in the cache key**, so a change busts the cache.
> - **Hold-aside check:** every digit, ₹ amount and date string in the English must appear
>   **unchanged** in each translation, or that record fails. Print which string went missing.
>
> Spec — gates (`p4_gates.py`): run all five gates of `data-contract.md` §3, **as a pre-filter,
> cheapest first**: 1 alias floor → 2 expressibility → 5 provenance & freshness → 4 forbidden
> phrase → 3 read-back completeness **last**. A record failing a gate does not go on to the next.
> Print a scheme × gate table; each failed cell shows the failing clause.
> - **Gate 1:** ≥3 aliases per language, ≥1 code-mixed per non-English language; an alias on ≥3
>   schemes is dropped from all of them; an alias on exactly 2 is kept.
> - **Gate 4, tier 1** (our voice — fixed lines, `summary`): bare words banned — eligible, qualify,
>   entitled, you will get, you can get · पात्र, हकदार, मिलेगा, पा सकते हैं · पात्र, हक्क, मिळेल,
>   मिळू शकते. **Tier 2** (verbatim source sections): **second-person claims only** — you are
>   eligible / you will get / you can get · आप पात्र / आपको मिलेगा · तुम्ही पात्र / तुम्हाला मिळेल.
> - **Brand allowlist** (HAQDAAR / हकदार and its Marathi inflection) applies to
>   **`closing_farewell` only**, nowhere else.
> - **Gate 3:** all six chunks present in all three languages (18 entries). Audio is rendered in
>   Step 10, so for now the "rendered" half prints `PENDING` and does not count as a fail.
>
> Hard rules:
> - **One caller at a time (R1)** does not apply to the pipeline, but still: no worker pool, no
>   async fan-out. Calls run one after another.
> - Numbers (`MAX_SOURCE_AGE_DAYS`, alias floors, retry/timeout) live in `tunables.py`, never inline.
> - Never print or log a secret.
>
> **Done when** `make pipeline-gates` prints the table and **≥6 schemes pass every gate**, and a

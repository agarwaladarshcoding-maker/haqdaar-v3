# ~~T11 · The closed set the model is allowed to say~~

**Type:** `wayfinder:grilling` (HITL) · **Module:** Model · **Blocked by:** ~~T03~~, ~~T09~~ · **Blocks:** T17, T18 · **CLOSED 2 Sep 2026**

## Question

The single model call emits class, box, value, confidence, language. What exactly is in each set, and what happens when the model goes outside it?

## Resolution

### The ticket body was stale in three places

Written before T03, T08, T09 and T10 closed. Three of its six bullets were answered or void on arrival:

- **"Whose confidence gates the ladder"** — T03 killed the ASR's number. T08 then changed the *shape*: the model now **selects** from the keyword list rather than our code string-matching a transcript against it. If the model picks, there is nothing left for a match score to run on either. T03's replacement had no source.
- **"May the model emit a value the corpus has never seen"** — answered by T09: out-of-set is UNKNOWN. What remained open was whether it costs a *box* or a *turn*.
- **"The value vocabulary per box"** — T10 pinned the roster to seven; T22 is producing two of the lists. A dependency, not a decision.

What T11 actually owned: the output contract's shape, the class set, the refusal path, and one collision T10 created that nobody had looked at.

---

### 1 · The model emits three fields, not five

**`class`, `box`, `value`.**

**`language` is struck.** T08 pins language per call; Sarvam transcribes in the pinned language. The model receives text already in one language and has nothing to detect. A per-turn language field either does nothing or silently fights the pin. Mid-call switching belongs wholly to **T24**, which is free to make it a keypad affordance costing no model call at all.

**`confidence` is struck.** A model self-reporting confidence on a selection it just made is not evidence, it is a second generation. It cannot go in the LOG as proof and it cannot be tuned. T03 required a number we own.

**Replaced by structure, not a score:** every spoken answer is echo-confirmed **unconditionally**. T10 already priced this in (keypad 1 turn, spoken 2), so the arithmetic was already paid for. The alternative — model returns a transcript span, our code scores it against the keyword's aliases — was rejected: it buys a tunable dial we do not currently need and hands **T23** a tuning problem days from freeze.

**T23 therefore inherits a ladder with no number, and does not need one.**

The `value` is validated against the closed set **in code after the model returns**, never trusted from the prompt. T08 named the system prompt as the only remaining guard once the verifier went. A prompt is not a guard. The code gate is.

### 2 · Five classes, not seven

Test applied: **two labels are one label if the system does the same thing after both.**

| Class | Caller did | System does |
|---|---|---|
| `ANSWER` | gave a usable value — for the asked box **or an earlier one** | tick the box named in `box`, move on |
| `CLARIFY` | does not understand the question | speak the simpler version of *this* question |
| `REPEAT` | did not hear | replay the same question, unchanged |
| `META` | wants another language, a person, or out | leave the ladder |
| `UNCLEAR` | said words, none of which fit | replay unchanged, count it |

**CORRECTION is struck** — it is an `ANSWER` pointing at an earlier box, and T09 already established there is no undo: a correction overwrites one box and re-derives. The `box` field already carries the distinction.

**NOISE is struck** — silence and non-speech produce an empty or near-empty transcript, which **code catches before any model call is made**. No tokens spent, no classification risk. NOISE was never a model class; it is a code branch upstream.

**QUESTION and CONFUSION merged into `CLARIFY`** — the distinction changed nothing downstream.

**`CLARIFY` and `REPEAT` were NOT merged**, and the four-class version was overturned on this: they need **opposite** responses. *"Kya matlab?"* needs different words; a barking dog needs the *same* words. One canned line is wrong for one of them whichever you pick. On a scheme IVR for feature-phone callers, "what does that mean?" is among the most common things anyone will say — these are precisely the callers who do not know what *social category* or *income band* mean. Collapsing that is designing for the caller we wish we had.

#### Two precedence rules — code rules on the output, not hopes about the prompt

1. **`ANSWER` beats `CLARIFY`.** *"Bihar. Aur ye income band kya hota hai?"* is both. Classifying CLARIFY discards Bihar and re-asks a question already answered. **Losing a value is worse than delaying an explanation.** Any utterance containing a usable value is an `ANSWER`.
2. **`META` beats everything, including `ANSWER`.** *"Marathi mein bolo, main shetkari hoon."* ANSWER-wins would bank "farmer" and strand the caller in a language they cannot follow. META is the only class where carrying on is *actively harmful*.

Order: **`META` > `ANSWER` > `CLARIFY` > `REPEAT` > `UNCLEAR`.**

#### Safety property that makes five affordable without a verifier

No **class** error can produce a T04 untruth. Mislabelled CLARIFY→UNCLEAR yields a repeat instead of a rephrase: annoying, recoverable. The only path to an untruth runs through a **wrong value**, which the closed-set code gate bounds to the wrong item off a known list, which echo-confirm catches. **The cost of a class error is degraded politeness, never a false statement about money.**

#### Build cost

`CLARIFY` needs one simpler rephrase line **per box** (7 × 3 languages = 21 short lines). `REPEAT` and `UNCLEAR` reuse existing question audio — zero new lines. `META` needs ~3 fixed lines × 3 = 9. **~30 short lines, rendered at ingest.** Not a real trade.

#### New constraint handed downstream

Every class charges against T10's 8-turn cap, including CLARIFY, REPEAT and UNCLEAR — the caller's time is spent regardless of cause. So: **two consecutive non-ANSWER turns on the same box drops that box to keypad.** This fires well before the cap and is a new input to **T18**.

### 3 · Two call shapes: the opener is not a question

T10 scored questions assuming **one question fills one box**. The opener is not a question. *"Main Bihar mein kisan hoon, mujhe kheti ke liye paisa chahiye"* is `state`, `occupation` and `category` in one breath. T09's box vector handles it mechanically; **T10's arithmetic assumed it could not happen.**

- **Opener call** → returns a **list** of `(box, value, span)` triples, zero or more.
- **Question call** → returns **exactly one** `(box, value)` pair. The box may be any of the seven, not only the one asked — that is how a correction lands.

Letting question calls write multiple boxes would reopen every hole T10 just closed. Letting the opener write only one throws away free boxes T06 and T10 both counted on.

#### The span guard — the load-bearing addition

Open-ended extraction is where a model is **most** prone to helpful invention. Given *"main kisan hoon"*, a model will reasonably also return `income_band = low`. Farmers are poor — and **the caller did not say it**. A filled box appends a mask and **narrows**, so an inferred value can exclude a scheme the caller actually qualifies for, and the LOG records it as though the caller said it. That is a T04 untruth, generated by helpfulness, invisible at runtime.

**Every value returns with the transcript span that produced it. Code drops any pair whose span is not literally present in the transcript.** String containment, no judgement.

This is not the span rejected in branch 1. That one was a **score**, a number to tune. This is **provenance**: checkable evidence the caller said the thing. Different job.

The model can still be wrong about which value a span maps to — that is the closed-set gate's job, and echo-confirm catches the rest. It can no longer invent a box from nothing.

#### One confirm covers the bundle

Three separate confirms would cost 4 of 8 turns before a single question. Instead: **one line assembled from cached keyword audio** — *"Bihar, farmer, farming support — correct?"* — one yes/no.

**The opener costs 2 turns whatever it fills**, exactly T10's spoken price, unamended. Filling nothing costs **1**.

**On "no": all opener boxes drop back to UNASKED** and the ladder asks them one at a time. No disambiguation logic, no extra turn. It occasionally loses good values and the ladder recovers them at normal price. It cannot produce an untruth, which is the only property required.

### 4 · `UNKNOWN` is a reserved value, not a sixth class

Present in **every box's closed set**. Covers both *"I don't know"* and *"I'd rather not say"* — same instruction to the filter, and the LOG stores the span verbatim so a reader can tell which it was without extra machinery. `social_category` is the live case.

A sixth `DONTKNOW` class was rejected on two grounds:

- **The span guard already prevents the dumping-ground failure.** `UNKNOWN` needs a span like any value. If the caller said "Bihar" and the model returns UNKNOWN, there is no declination phrase to point at, the pair is dropped, and it falls to `UNCLEAR` and re-asks. A class carries no span and would have no such guard.
- **A class would force re-derivation of the precedence chain.** A reserved value inherits it free: *"Bihar, baaki pata nahi"* is simply an `ANSWER`.

Rules:

- Written only by the caller declining/not knowing, or by a keypad drop receiving no press
- **Accepted first time. Never re-asked, never pushed to keypad.** A declining caller must not be marched onto a keypad menu for caste — that is the worst available behaviour in this system, and it means declination does **not** count as a failed turn under §2's two-strike rule
- Echo-confirmed like any other value — a false UNKNOWN can only fail to narrow, never wrongly exclude, but the uniform 2-turn price keeps T10's arithmetic unamended
- **The opener never emits UNKNOWN** — with no asked box there is nothing to attach to, and an unmentioned box is simply UNASKED, which already works

#### The rule T09 and T10 left unstated

A caller answering "don't know" to everything exposed it. T09 said UNASKED and UNKNOWN are the same instruction to the filter; T10's speaking rule bars a scheme non-`ANY` on an **unasked hard box**. Nobody said whether UNKNOWN counts as asked.

**It counts as NOT satisfied, identically to UNASKED.** Otherwise a caller declining to state their state hears schemes they are geographically barred from — exactly the failure T09 introduced the rule to prevent. Consequence: a caller who answers nothing hears only schemes `ANY` on every hard box. Honest, a correctly-executed dead-end, and **T04 already scores that a pass.**

**The only real difference between UNASKED and UNKNOWN: UNASKED is still askable. UNKNOWN is removed from T10's askable pool and never revisited.** That is the distinction T09 gestured at and did not name.

### 5 · Model, clock and refusal path

#### The latency budget

T10's ~8 s/turn is not 8 s of model: caller speaks (~3 s) → Sarvam finalises (~0.5 s) → **model** → Mouth plays a cached file (instant, on disk). The model gets **under a second** to feel natural; past ~1.5 s the caller starts talking again believing the line died. Output is ~30 tokens, so generation speed is irrelevant — **time-to-first-token dominates, and that scales with prompt size.**

#### Prompt size is asymmetric — the finding that makes the token maths survivable

A **question call** knows its box and needs only *that box's* list (`gender` 2 values, `state` 36): a few hundred tokens. The **opener** needs all seven: ~1,500 tokens. **The opener is the expensive call; every question after it is cheap.**

Full call ≈ 1,500 + up to 8 turns × ~300 ≈ **4,000 tokens.**

#### The free tier is where this design dies

| | Groq free | Gemini free |
|---|---|---|
| TPM | 6,000 | 250,000 |
| Calls supported | **~1.5 per minute** | ample |
| RPM | 30 | 10–15 |
| Concurrent callers | dead on tokens | **~2** |

Groq is out — fastest available, and 6,000 TPM is one and a half phone calls. Gemini's free tier survives on tokens but its **RPM cap allows ~2 simultaneous callers**; T04 wants ten calls from outside the team on real handsets, and two coincident dials produce a 429 mid-sentence.

**Verdict: turn billing on.** Ten calls × 4,000 tokens ≈ **40,000 tokens for the entire demo** — cents on any Flash-Lite-class rate. **The cheapest risk removal in the project**: the largest runtime failure mode deleted for less than a bus fare. The free tier's remaining role is **offline testing against the keyword table** (T08's test base).

#### Which model

**Gemini Flash-Lite class, paid key, model ID pinned and re-verified in demo week.** Flash is the upgrade if quality disappoints. Pro is unnecessary and now behind billing regardless.

The model is not reasoning. It picks one item off a list of at most 36 and labels the reply as one of five things — close to the easiest job available. Spending on reasoning quality buys nothing here.

*(Published free-tier figures disagree across sources and preview model IDs churn. Since we are paying, this is a check, not a risk.)*

#### Refusal path

| Failure | Response |
|---|---|
| Malformed output | `UNCLEAR`, re-ask. **Do not retry the model** — a retry doubles the wait and the caller has already gone quiet |
| Timeout (>1.5 s) | cancel, `UNCLEAR`, logged as timeout not misunderstanding |
| Value outside closed set | `UNCLEAR` (§2) |
| Span absent from transcript | drop the pair (§3) |
| 429 / 5xx / provider down | straight to keypad-only |

**Two model failures in one call drops the whole call to keypad-only. Do not limp.**

Arithmetic, not caution: T04 fails a call for ending **before a terminal state**, and keypad-only **is** a terminal state and a pass. A call retrying a broken model burns T10's cap and ends with nothing — a **fail**. Failing over early converts a certain fail into a certain pass.

#### No second model provider

Groq-as-failover behind Gemini was considered and **rejected**: a second prompt to tune, a second set of quirks to test, a second thing that can be down — days from freeze with no verifier. **The fallback is the keypad**, already designed, already deterministic, already a pass. The keypad is a better fallback than any model because it cannot be wrong.

Temperature 0, structured output enforced, no streaming (a 30-token response is useless partially).

### 6 · What the model is shown — the two-turn window

Never asked by the ticket; unbuildable without it.

Each call is given **five** things:

1. The caller's latest utterance
2. Which box was just asked (blank for the opener)
3. That box's value list — all seven lists for the opener
4. The ticked boxes so far (`state=Bihar, occupation=farmer`)
5. **The previous 2 turns, verbatim**

Adarsh proposed feeding the **full conversation** every call, reasoning that a whole call is only a few hundred tokens. **The cost objection does not hold and was withdrawn**: a call is ~60–150 spoken words; Devanagari costs roughly 2–3× English per word, so a full Marathi call is ~600–1,200 tokens — fractions of a cent, and ~50–100 ms of added TTFT against a one-second budget. Note also that "the whole convo, that is the LOG" does not follow: T09 stores **no transcript**, only snapshot id + box vector, which is already item 4. The proposal adds **raw spoken words**, a different artefact.

Full history was rejected on two grounds that are not cost:

- **It guts the span rule.** The guard's power comes from the haystack being **one sentence**. Caller says at turn 1 *"my brother in Bihar told me about this"*; at turn 5 they mumble; the model returns `state = Bihar` with span "Bihar" — **and the span check passes**, because those words really were said. A state the caller never claimed is now stamped, narrowing, and in the LOG as though claimed. Widening the haystack weakens the guard in exact proportion.
- **It breaks T08's offline testability**, which T08 made load-bearing: the inbound leg is testable against a table of utterances without placing a call. That holds only while **one utterance produces one output**. With history the same sentence varies by what preceded it, and the test space stops being a list and becomes a tree — the thing to protect hardest with no verifier. The model would also read its own earlier outputs, so a turn-2 mislabel becomes turn-5 established fact.

**Resolution — the two jobs are split.** Context for *understanding* and evidence for *stamping* get different scopes:

- **A rolling 2-turn verbatim window**, giving corrections with no noun in them (*"no, not that one"*), pronouns, and rephrase-awareness. Bounded, so latency and test space stay bounded — at most triples, not whole calls.
- **The span check remains scoped to the current utterance only.** The model may *read* the last two turns; it may only *quote* from the sentence just spoken. One string comparison enforces it.
- **A per-box counter** — times asked, how the last attempt ended — which is what actually fixes rephrase loops, at ~10 tokens instead of a transcript.

The opener is unaffected; nothing precedes it.

**No raw transcript history beyond the window. Temperature 0. Same input, same output.**

**Empirical settlement:** T08 already requires the offline test table. Run the same ~50 utterances through **four fields**, **four + two turns**, and **full history**, and count wrong stamps. An afternoon, and it converts this from argument to measurement. Prediction on record: the two-turn window beats four fields on corrections, and full history loses on invented values. **Added to T13's dry-run.**

## Amendments to closed tickets

- **T10** — the ladder starts from **whatever the opener filled and the caller confirmed**, not an empty vector. Scoring is unchanged (minimax elimination ÷ expected turns already runs over remaining boxes and current survivors); it needs a seeded start. Two favourable knock-ons: T10's speaking rule is already satisfied for any hard box the opener filled — typically `state`, the expensive wall T10 refused to make mandatory — and the budget shape becomes opener 2 + 6 remaining, which is what T10 designed for.
- **T09** — **UNKNOWN counts as not satisfied for T10's speaking rule**, identically to UNASKED. The sole difference between them is that UNASKED remains askable.
- **T20** — **scope widened from "call audio" to "call audio and transcripts."** Under T08 the audio never approaches the model; **the transcript does.** *"I'm a Scheduled Caste farmer in Bihar earning under ₹50,000"* is more sensitive as text than as sound, and text is what crosses the border. Unwidened, T20 returns an answer to a question we did not need. Escape hatch if restrictive: Gemini via Vertex offers an India region — not a blocker, but it determines which key gets created.

## Open check handed to Audio

T08 has the caller's words becoming English inside the system. If Sarvam's translation performs that hop, **confirm it returns both the original-language transcript and the English** — the LOG needs the original as proof of what was said. The span check works either way, comparing the model's quoted words against whatever text the model was handed.

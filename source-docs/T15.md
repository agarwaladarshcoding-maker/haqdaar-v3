# T15 · How Mouth gets its audio

**Type:** `wayfinder:grilling` (HITL) · **Module:** Audio · **Blocked by:** ~~T08~~, ~~T24~~, ~~T14~~ · **Blocks:** T17 · **Closed 9 Sep**

## Question

The architecture decision is made — TTS behind an ingest-time cache. This ticket turns it into an interface someone can own.

To resolve:

- Where rendered audio lives.
- Which strings are rendered at ingest and which may render live, with a hard ceiling on live-rendered length.
- The template set: every sentence the system can ever speak, enumerated, per language.
- Fallback when TTS is unavailable mid-call.
- Codec and sample rate handoff to the provider, from T01.
- Who owns this module.

## Why it blocked T17

Mouth is the last thing before the caller's ear, and it consumes the output of both the corpus and the turn clock.

## Resolution

Two findings collapsed half the question list before branch one:

- **Nothing fetches anything.** T14 pinned playback as push-down-the-socket (`playAudio`/`checkpoint`/`playedStream`/`clearAudio` on the WSS we already hold). There is no URL, no HTTP serve, no provider-side fetch. "How the provider fetches them" was not a question with an easy answer — it was not a question.
- **At 8 kHz μ-law the whole corpus is ~200 MB.** 8,000 bytes/second; a 35-word `summary` is ~120 KB; a whole scheme in one language is ~600 KB. The 12 Sep corpus fits in RAM on the box. Tiering, lazy fetch, and eviction were all answering a question that doesn't exist at this scale.

### Where rendered audio lives

One flat content-addressed pool on local disk, plus one manifest per snapshot; **the snapshot is the manifest**, not a directory.

- Pool: `audio/<render_key>.ulaw`, flat, never pruned mid-call.
- **Render key = `sha256(text ‖ lang ‖ voice_id ‖ tts_model ‖ 8000)`.** Text alone is wrong — a voice change would silently make every cached caller hear last month's read-back. The key is the whole render contract.
- Manifest: `snapshots/<n>.json`, logical key → render key. Deploy renders missing keys into the shared pool, writes the manifest, flips the pointer (rev 3, unchanged).
- **A call loads the manifest at connect and holds it to hangup** — rev 3's pin, extended to cover audio, not just text: a mid-flight deploy must not change what a running call says.
- Orphan sweep: mark-and-sweep over the union of live manifests, between deploys only. At ~200 MB total, **we will not sweep before 12 Sep and nothing is harmed.**

Rejected: an object store. It buys durability for an artifact that's regenerable from the corpus by definition, and buys a network hop in the exact place T14 spent a session shaving milliseconds out of.

### Ingest vs live — the ceiling is zero

**There is no live rendering.** The default's 4-word ceiling is overturned down to zero, and charting's "only short echo fragments render live" is repealed.

The default assumed echo fragments were unbounded. They aren't — T08 froze the inbound keyword list at ~150–200 values per language, and T11 forbids the model from composing free text. Walking every path that speaks, nothing survives as uncomposable-in-advance: keyword echoes are the closed set, box labels are the box roster, widening announcements are four fixed lines, scheme text is the corpus. **Every string the system can ever speak is enumerable at build time**, so TTS is a build tool, not a runtime dependency.

Enforcement is mechanical, not review: **the runtime process does not hold TTS credentials.**

Composition rule, the one real call in this branch:

> Compose from separately-addressable files only where the pieces must be independently addressable at runtime. Everywhere else, render the whole sentence.

- Fixed lines → one file, whole sentence.
- **Echo-confirm and question lines that carry a box value → one file per (line, value, language), not carrier + slot.** A concatenated slot needs the value to inflect correctly in Hindi/Marathi; getting the case wrong at a join reads as broken. The cross product is manageable (~200 values × 3 languages ≈ 600 files, ~30 MB) — buying grammatical correctness for 30 MB isn't a trade.
- **Scheme audio → concatenated from its six per-scheme chunks** (name, summary, four verbatim sections), because T06 exposes the sections individually by keypad and T14 needs a checkpoint boundary immediately before the name. This family stays composed because the pieces are genuinely independently addressable.

### The template set

Enumerating rather than estimating:

- **Flat lines, N₁ ≈ 12**: opener question · didn't-get-that · results preamble · dead-end preamble · overflow line · section menu · anything-else · closing line · silence rung-2 presence (T14) · keypad-only entry · Door A two-candidate carrier · one reserved for T18's open Door-A→Door-B question.
- **Per-box, N₂ ≈ 17** across the six askable boxes: question form ×6, rephrase form ×6 (T11's ask-counter implies a second form exists; it has never been written), keypad menu ×5 — not 6, because `state`'s 36 values fail the cardinality rule below.
- **N = N₁ + N₂ ≈ 29. Fixed inventory = 3N + 1 ≈ 88 files** (the +1 is T24's one non-per-language trilingual greeting).
- Separately, **value inventory** for the box-value carriers above: ≈ 200 values × 3 languages ≈ 600 files, ~30 MB.
- Separately, **scheme inventory**: 6 chunks × schemes × 3 languages.

Two rulings fell out of the count itself:

- **Cardinality > 9 → the box drops straight to UNKNOWN, not keypad.** `state` has 36 values; no keypad menu covers that, and a region-then-state menu spends turns solving a problem UNKNOWN already solves safely (T09: UNKNOWN always widens, never narrows; T11: UNKNOWN is accepted first-time without a keypad push). **Amends T11.**
- **Every carrier that takes a slot must place it terminally or after a pause** — the constraint that keeps a future authored line from being unrenderable in the composed family.

### TTS unavailable mid-call

Dissolved by the ceiling-zero ruling: there is no live TTS to fail mid-call. The surviving question is a manifest entry with no rendered file at connect, and T06 already answers it: **a snapshot with any unrendered entry does not flip the pointer.** A missing file at runtime is a bug, not a condition, and falls into T11's existing keypad-only drop. The default's "cached greeting apology on TTS failure" is struck — it's a fixed line ×3 for a state that cannot occur.

### Codec and sample rate

μ-law, 8,000 Hz, mono, raw — stored exactly as it goes on the wire.

- Pipeline: TTS → WAV → `ffmpeg` → 8 kHz mono μ-law, stored as `.ulaw` (base64-encoded at load time, not at rest — the encode is microseconds and `.ulaw` stays inspectable).
- **One loudness-normalise pass at ingest, trim-then-pad to a fixed 120 ms tail on every file.** Load-bearing: the read-back concatenates six files, and a level mismatch between them sounds like a fault on a phone line.
- **One file per `playAudio` call. No slicing.** T14 already priced ~200–300 ms of `clearAudio` overrun as acceptable; slicing to shave it buys back something already paid for.
- **TTS vendor: Sarvam Bulbul, one voice per language, voice id folded into the render key.** Same vendor as Ear, Indian-language prosody. Provisional in the same sense as Deepgram — a swap is a re-render, not a design change, because the voice lives in the key.

### The interface — frozen for T17

One primitive, append-only:

- **`say(sequence)`** — an ordered list of audio refs and named marks. Appends everything to Plivo's FIFO in order, emits a provider `checkpoint` at each mark's queue position. Returns immediately; never blocks.
- **Completion is `playedStream(<mark>)`** — the only completion signal in the system (T14).
- T12's `t_name` is a mark placed between the preamble chunk and the name chunk; its `playedStream` fires when the FIFO reaches that boundary — a provider-timed measurement, not a local guess, because the name is its own file.
- **`clear()`** → `clearAudio`, awaits `clearedAudio`. Keypad-triggered only.
- **`repeat()`** replays the last sequence verbatim, marks included — a one-slot buffer of the last `say()` call. Marks re-fire, so a `*`-triggered re-read writes a second `t_name` beside the first, exactly as T24 specified for `#`.

### Ownership

**The manifest is the module boundary.** The renderer is a function of the corpus, runs at ingest, ships inside the snapshot — a Data build tool wearing Mouth's name. **Audio owns `say()`/`repeat()`/`clear()`, the mark contract, and the manifest reader.** Data's fake is a manifest of silence files; Audio's fake is a `say()` that logs and fires `playedStream` on a timer (rev 3 precedent) — neither owner writes a fake for the other's side.

## Downstream amendments

- **T11**: cardinality > 9 drops to UNKNOWN, not keypad.
- **T06**: a new build gate, same shape as the alias floor — a scheme missing any of its six read-back chunks in any language does not enter the snapshot.
- **T07**: inherits T06's new gate.
- **T17**: gets the `say`/`repeat`/`clear` primitive and the manifest as a second frozen interface.
- **T19**: gets a sizing number — ~200 MB total, servable from local disk and RAM, no object store needed for 12 Sep.
- **T23**: inherits the cardinality carve-out to word, plus the ~29-line fixed template set (× 3 languages) to actually write.

## New fog

- **The rephrase form was never costed.** T11's per-box ask-counter implies a second sentence per box; nobody has written it. Six boxes × 3 languages, discovered by this ticket's enumeration, belongs to T23.
- **Sarvam Bulbul's Marathi at 8 kHz is unheard.** Not a design question — a day-one check for the Audio owner. The render key makes a vendor swap cheap if it's bad.

# T24 · How the call's language is chosen, and whether it can change mid-call

**Type:** `wayfinder:grilling` (HITL) · **Module:** Audio · **Blocked by:** — · **Blocks:** T14, T15, T17

**Status: CLOSED 9 Sep 2026.** Resolution below. MAP rev 17.

*(Renumbered from T21 on 23 Aug — a parallel session had already claimed that number for "What the record says about provenance and freshness".)*

## Question

[[tickets/T03|T03]] recommends pinning `language_code` per call rather than running the ASR on auto-detect, because pinning buys accuracy on the weakest language. Pinning makes the language choice an explicit design decision instead of something the model does quietly.

- How is the pin set at the top of the call — a keypad prompt (1 Hindi, 2 English, 3 Marathi), the dialled number, or something else?
- What does the greeting sound like before the language is known? It has to be intelligible to all three callers, in a system where Mouth serves pre-rendered files.
- Can the caller change language mid-call, and if so by what gesture? Sarvam's realtime socket takes a `config.update` at the next utterance boundary, so it is cheap to allow — the question is whether allowing it is worth the state it creates.
- Does a language change clear any caller facts, or does it behave like "anything else?" and keep everything but the need box?
- Does a code-mixed caller — pinned to Marathi, speaking half English — need special handling, or does `mode="codemix"` absorb it?

## Why it blocks

T15 (how Mouth gets its audio) needs to know how many language variants of every line exist and when the language is known, since the pre-render happens at ingest. T14 needs to know whether the first turn is a language prompt or a real question, because that changes the turn budget.

## Interaction with T02

Rev 5 ruled English myScheme content the only source of truth, with every spoken Hindi and Marathi line human-verified by us. That makes each additional language a verification bill, not a translation call — which raises the stakes on whether mid-call language switching is worth supporting at all.

## Default if this stalls

Keypad language selection as the first thing after a short trilingual greeting; the pin holds for the whole call and cannot be changed; a caller who wants another language hangs up and redials. Costs one turn, buys total simplicity.

# Resolution

**Code-mix in, chosen language out.** The caller may speak however they like on every turn of every call, in any mixture of the three languages; the system always speaks back in the one language the caller picked at the top, and changes it only when told to by keypad.

The ticket's own default is **overturned on switching** and **held on selection**. The five branches:

## 1 · How the pin is set — keypad only, before anything else

**Auto-detect is rejected**, and not on latency grounds — the cost is elsewhere:

- To detect you must already be running the socket, and the first utterance *is* the opener (T12) — the turn carrying Door A's `scheme` pseudo-box and box 0 `category`. Auto-detect degrades exactly the turn that can least afford it, then re-pins for turn 2 once the damage is done.
- **It inverts T03's own finding.** Pinning buys accuracy on the weakest language; a detector on ambiguous 8 kHz audio biases toward the better-represented ones. Auto-detect systematically degrades the Marathi caller the pin was protecting.
- **It breaks T08's offline test base**, which is the objection held hardest. The inbound leg is testable against a table of utterances *because* the transcript is a function of text plus a known pin. Make the pin a function of the audio and the table becomes a recording session.
- **T16 cannot explain it.** There is no confidence number anywhere in this design, so a wrong stamp caused by a wrong detection leaves nothing in the trace a reader can reconstruct — a bad value with no visible cause.
- **Output flapping.** One English word inside a Marathi sentence flips the detector, and the system answers in English. To suppress that you need hysteresis, which is more hidden state than the keypad — except the caller cannot command it.

**Speech selection is rejected by construction**: accepting *"Marathi"* as a spoken answer needs an ASR pinned to the language you are trying to determine, on a one-word utterance, on a noisy line.

**Per-DID routing (three numbers) is rejected for the bar, not on merit.** It costs zero turns, the strongest argument available for it, but it moves the problem into how the number is publicised and the acceptance bar says *a* live Indian number. Filed as fog, not killed.

This is **the one input in the system where the keypad is forced rather than merely preferred** (T10 prices it as preferred everywhere else). DTMF on the Plivo socket (T01) is the most reliable channel in the design, and the single irreversible decision rides on it.

**Invalid digit or no input:** re-play the line once, then default to **Hindi** and proceed. A hangup is an unprompted hangup and T04 scores that a fail; a mis-served caller still reaches a terminal state and still has `*`. The LOG records `lang_source: keypad | default` — same shape and same justification as T11's `unknown_source`.

## 2 · The greeting before language is known — one trilingual file

- It is **the only audio file in the system that is not per-language.** The fixed-line inventory handed to T15 is **3N + 1**, not 3N.
- One clause per language, ≤ 3 s each, naming only the digit. No welcome, no brand sentence, no consent line — every second here is paid three times.
- **Keypad barge-in (rev 2) makes the ordering nearly free**: a returning caller presses immediately and never hears clauses two and three. Ordering serves only the first-time caller, who hears all of it regardless.
- **1 Hindi, 2 Marathi, 3 English** — overturning the ticket body's 1/2/3. Marathi is the weakest-served caller in the design (weakest ASR, T03), so clearing them out of the preamble ~3 s sooner is the cheapest kindness on offer, and English speakers can parse the Hindi clause's shape anyway. Recorded as **reversible at zero cost** — nothing downstream reads the order.

## 3 · Mid-call switching — allowed, keypad-only, reserved `*`

The default said the pin holds for the whole call and a caller who wants another language redials. It rested on a cost that does not exist:

- **Mouth cost: zero.** T04 already requires all spoken content tri-lingual at parity, so every file a switch needs was rendered at ingest.
- **T08 verification cost: zero.** Same reason — parity was already bought.
- **Sarvam cost:** one `config.update` at the next utterance boundary.
- **Engine cost: zero.** T09 made the Engine language-blind and pure code. The box vector holds *codes*; `state=BIHAR` has no language.

What remains is the routing, and it resolves T11's handoff the opposite way to how T11 framed it:

> **The speech route to a language change structurally cannot work.** To hear *"can we speak in Marathi?"* you must understand a caller you have just established you cannot understand. A mis-pinned caller speaking the wrong language yields garbage transcript — `UNCLEAR`, not `META`.

So **`META` is not the language route.** The keypad affordance T11 offered as an option is the one taken, and it is the only route that works precisely when it is needed.

- **`*` at any time re-plays the trilingual line and re-pins.** T24 claims `*`; **`#` is left unclaimed** for T14 / T23's "repeat".
- **A switch keeps everything** — stricter than "anything else?" (rev 2), which clears the need box. A switch clears *nothing*, because it is the same question in different words. Every stamped value was either keypad-entered (language-independent) or survived T11's unconditional echo-confirm, and a caller who could not follow the confirm would not have confirmed — they would have burned two non-ANSWER turns and dropped to keypad.
- **No cap on switches.** A `*` press is unbounded in count but bounded in damage. Handed to T14: the **wall-clock call cap, not the turn counter**, is what bounds turn-0 events.
- **`*` during the read-back re-reads in the new language** — free, the files exist. `t_name` is stamped on the first read-back and the bar reads the first; a post-switch re-read writes a second stamp beside it, exactly as T12 stamps both readings rather than choosing one.

## 4 · Code-mixing — absorbed, and now unconditional

**`mode="codemix"` is ON for all three pins, always.** Not a per-call decision, not a flag to evaluate — a requirement Audio verifies at integration. If the flag turns out not to exist, behaviour is unchanged, because the thing that actually absorbs code-mixing is **T08's English hop plus T11's span guard comparing the span against the transcript rather than against a vocabulary.**

- Pinning `mr` does not tell Sarvam to reject English tokens; it tells it what base to expect. *"मी farmer आहे, mala scheme पाहिजे"* transcribes and translates cleanly under a Marathi pin. **The caller who mixes every sentence is served by the design as it already stands.**
- **Nothing in the design may depend on the flag.**

**The one place code-mixing bites is T12's alias contract, and it bites hard.** Scheme names are proper nouns nobody translates, so the honest Hindi and Marathi alias sets are *mostly* code-mixed. **T24 amends the contract: for each non-English language, at least one of the ≥3 aliases must be the code-mixed form.** Three pure-Marathi aliases for *PM-KISAN* are three strings no caller will ever say, and the build-time uniqueness gate would pass them.

## 5 · Turn accounting — turn 0

**Language selection is turn 0. It writes a LOG line and does not count against the 8-turn cap.**

- T16 requires that `turn_n` and the cap count the same thing. They still do — one monotonic counter. **The cap is a predicate on that counter (`1 ≤ n ≤ 8`), not a claim that every line is a cap turn.** Turn 0 fills no box, asks no question and makes no model call.
- The alternative takes T10's arithmetic from *opener 2 + 6 questions* to *5 questions*, spending a narrowing turn on a mechanic.
- **T16 amendment:** the LOG gains language, written **once at call open and once per switch, never per line.** By T16's own derive-don't-store rule, language is state and reconstructible from open plus switch events; it is not a branch the code took, so it is not a `ladder_rung`-class exception.

## Rejected, and why it is written down

**Detection as a hint that never switches anything** — if `*` proves undiscoverable, run a detector whose only power is to play one line offering the switch when it disagrees with the pin for two consecutive turns. Determinism, the test table and the trace all survive, because detection prompts and never acts. Costs one fixed line ×3. **Not for 12 Sep**; named as the dial to turn if the demo shows callers stuck in the wrong language.

## Handoffs

- **T14** — unblocked. Inherits turn 0, the `*` event, `#` left free, and the requirement that turn-0 events be bounded by wall-clock rather than the turn counter.
- **T15** — one blocker left (T14). Inherits **3N + 1** and the fact that language is known before any non-greeting file is served.
- **T16** — amended: language written at open and at each switch.
- **T12 / T07** — alias contract amended: one code-mixed alias minimum per non-English language.
- **T11** — `META` confirmed as *not* the language route.
- **T17** — one of its four remaining blockers cleared.
- **Build (out of scope, rev 2):** the deferred consent line **cannot sit at greeting** — trilingual, it triples the preamble. It goes after selection, in one language.
